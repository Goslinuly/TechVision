# Модель решения (§5 ТЗ)

Документ описывает алгоритмическую модель Aqıqat — для защиты и Q&A. Всё
изложенное реализовано в коде; ссылки на файлы приведены.

## 1. Общий конвейер (агентный цикл, §2.1)

`orchestrator.analyze(text) → Card` (`app/orchestrator/orchestrator.py`):

1. **Определение языка** kk/ru по казах-специфичным буквам (`services/lang.py`).
2. **Классификация + декомпозиция** на атомарные утверждения — дешёвым Haiku /
   Groq, с детерминированным фолбэком (`_extract`). Каждое утверждение →
   `checkable` (проверяемый факт) или `opinion` (мнение/домысел — не проверяем).
3. **Маршрутизация проверяемых утверждений** — кастомный tool-use цикл
   (Fable 5 / Groq Llama 3.3), модель сама выбирает инструменты:
   `search_local_corpus`, `google_factcheck`, `kazllm_specialist`.
   Устойчивость: при ошибке/лимите LLM — детерминированный путь по тем же
   реальным инструментам.
4. **Детектор манипуляций** — всегда, по всему сообщению (`tools/rhetoric.py`).
5. **Синтез карточки** (§4): структура, а не вердикт.

## 2. Семантический поиск (retrieval)

`tools/local_corpus.py` — три бэкенда, выбираются в рантайме:

| Приоритет | Бэкенд | Порог τ |
|---|---|---|
| 1 | **pgvector** (e5 + Postgres/Supabase) | `settings.tau_cosine = 0.84` |
| 2 | **e5 in-memory** (cosine по корпусу) | `0.84` |
| 3 | **lexical** (Jaccard по токенам, fallback) | `TAU = 0.18` |

e5 = `intfloat/multilingual-e5-base` с префиксами `query:`/`passage:`
(`services/embeddings.py`); векторы нормализованы, cosine = скалярное
произведение. Совпадение засчитывается при `similarity ≥ τ`.

## 3. Формула уверенности (confidence)

`orchestrator.compute_confidence(local, google)` — уверенность в вердикте
утверждения, 0..1:

```
confidence = 0
если есть совпадение в локальной базе:
    sim = max(similarity совпадений)
    confidence += 0.5 · min(1, sim / τ)      # вес similarity
    (если similarity недоступен — фиксировано +0.35)
если вердикт найден в Google Fact Check:
    confidence += 0.45                        # внешнее подтверждение
confidence = min(confidence, 1.0)
```

Т.е. уверенность растёт с (а) близостью к известному фейку в базе, (б) наличием
независимого подтверждения в Google, (в) ясностью рейтинга источника.

### Почему максимум 0.95, а не 1.0

Веса подобраны так, что даже при совпадении обоих независимых сигналов
(`sim ≥ τ` **и** вердикт в Google) сумма равна `0.5 + 0.45 = 0.95`. `min(…, 1.0)`
в коде — защитная обрезка на случай изменения весов, а не рабочая граница.

Это сделано намеренно, а не забыто:

- **1.0 означало бы «машина уверена абсолютно».** Продукт построен на отказе от
  таких утверждений (см. USP: не «97% фейк», а разбор). Формула не должна
  говорить того, чего не говорит интерфейс.
- **Оба наших сигнала — вторичны.** Локальная база и Google Fact Check — это
  «кто-то уже проверял похожее утверждение», а не проверка *этого* утверждения
  здесь и сейчас. Даже идеальное совпадение с записью фактчекера не устраняет
  риск, что перед нами другая формулировка/другой случай.
- **Оставшиеся 0.05 закрывает только человек** — фактчекер, подтверждающий
  конкретное утверждение. Это же место, где в roadmap стоит human-in-the-loop.

Практическое следствие: в карточке `confidence` подаётся как «насколько надёжна
найденная опора», а не как «вероятность, что это ложь».

## 4. Вердикты

`refuted` (❌ опровергнуто) · `supported` (✅ подтверждено) ·
`not_found` (⚠️ данных нет) · `not_checkable` (💭 мнение/домысел).
Маппинг рейтингов источников → вердикт: `tools/google_factcheck.py`,
`tools/factcheck_parser.py` (Ложь/Фейк/Манипуляция → refuted; Полуправда →
not_found; Правда → supported).

## 5. Детектор манипуляций

`tools/rhetoric.py` — каталог приёмов с указанием span'а (позиции фразы) для
подсветки в карточке (§4):

- `fear_appeal` — апелляция к страху;
- `unsourced_number` — конкретная цифра без источника;
- `false_dichotomy` — ложная дихотомия «или X, или Y»;
- `authority_appeal` — апелляция к безымянному авторитету;
- `us_vs_them` — противопоставление «свои/чужие»;
- `urgency` — искусственная срочность.

Правила покрывают ru и kk. Качество измеряется (§7).

## 6. Второстепенный сигнал по изображениям (§1)

`services/image_forensics.py` — **сигнал, не вердикт**. Открытые детекторы
дипфейков дают ~78% AUC, поэтому уверенный вердикт противоречил бы принципу
проекта. Возвращаем объяснимую подозрительность:

- **ELA** (Error Level Analysis): пережатие в JPEG и остаточная ошибка —
  редактированные/вставленные области отличаются по уровню ошибки;
- **EXIF/метаданные**: теги редакторов (Photoshop, GIMP…) и AI-генераторов.

Каждый результат несёт дисклеймер и используется только на собственном
демо-материале команды.

## 7. Метрики (доказательная база)

`scripts/eval.py` + `data/eval_set.json` → `EVAL.md`. Текущий прогон по
размеченному набору:

| Метрика | Значение |
|---|---|
| Точность языка kk/ru | 1.0 |
| Манипуляции: precision | 0.941 |
| Манипуляции: recall | 1.0 |
| Манипуляции: F1 | 0.97 |
| Отделение мнений | 1.0 |
| Попадание вердикта (корпус) | 1.0 |

Единственный false positive (`unsourced_number` на нейтральной статистике)
задокументирован честно — это ограничение rule-based детектора.
