# DEMO_SCRIPT — Aqıqat (Tech Vision 2026, оффлайн-финал)

Сценарий 4-минутного показа с экрана + чек-лист стабильности.
Критерий 1: «Стабильность демонстрации, UI/UX и уникальность продукта».
Регламент: **4 мин питч + живое демо MVP с экрана + 2 мин Q&A.**

- Боевой домен: **https://web-production-50fcb.up.railway.app**
- Бот: **https://t.me/Aqiqat_check_bot**
- Оркестратор: Groq (Llama 3.3 70B) с graceful-fallback на детерминированный разбор.

> Золотое правило демо: **не набирать текст руками на сцене**. Всё вставляем
> из заготовок (см. раздел «Заготовленные примеры»), примеры-чипы уже вшиты в лендинг.

## 1. Поминутный сценарий демо (4:00)

Открытые заранее вкладки браузера (слева направо, чтобы не искать в эфире):
1. Лендинг — `/`
2. `/health`
3. `/metrics`
4. Telegram Web / десктоп с открытым `@Aqiqat_check_bot`
5. Резервный скринкаст (локальный файл, НЕ ютуб — интернет может подвести)

### 0:00–0:40 — Проблема + вход (лендинг)
- Открыть **боевой домен** `/`. На экране hero: *«Разбираем ‘‘новости’’, а не пугаем вердиктом»*.
- Проговорить боль (1 фраза): школьнику/студенту в семейный чат прислали «новость»
  на казахском или русском — готовых инструментов проверки на **kk/ru с местным
  контекстом нет, рынок англоязычный.**
- **Показать переключатель RU / KK** (в шапке, справа) — кликнуть **KK**: весь
  интерфейс мгновенно на казахском. Это наш USP — **казахский контекст как первый класс,
  а не перевод.** Вернуть на RU для читаемости жюри.

### 0:40–2:00 — Живое демо: разбор (ядро показа)
- Прокрутить к секции **«Живое демо»**.
- Кликнуть по **чипу-примеру** (не печатать!). Рекомендуемый сильный пример:
  > «Врачи скрывают, что вакцина X вызвала 5000 смертей в Алматы. Срочно перешлите всем!»
  Он бьёт сразу по трём приёмам: апелляция к страху, цифра без источника, искусственная срочность.
- Нажать **«Разобрать»**. Пока идёт запрос — одна фраза вслух: *«тот же разбор придёт
  и в Telegram-боте, движок один».*
- Разобрать вслух **карточку-разбор**, показать пальцем/курсором:
  - **✅ Проверяемые утверждения** — каждое атомарное утверждение с **цветным бейджем
    вердикта** (❌ опровергнуто / ✅ подтверждено / ⚠️ данных нет / 💭 мнение) и **шкалой
    уверенности** (проценты — это `confidence`, а не «97% фейк»).
  - **🎭 Манипулятивные приёмы** — **подсвеченные `<mark>` фразы** прямо в исходном тексте;
    навести курсор — во всплывающей подсказке название приёма и объяснение.
  - **💬 Как ответить** — готовая вежливая формулировка **на языке сообщения**, которую
    можно отправить обратно в чат.
  - **Кнопка «Поделиться в Telegram»**.

### 2:00–2:40 — Web-карточка `/r/{id}`
- В блоке ответа нажать ссылку **«Открыть полный разбор →»** — откроется страница
  **`/r/{id}`**. Это **шаринговая карточка**: та же структура, но по постоянной ссылке —
  ею делятся в чат вместо пересланного фейка.
- Показать внизу дисклеймер: *«Aqıqat не выносит вердикт ‘‘97% фейк’’… Решение — за вами.»*
  Проговорить: **честность — это фича, а не слабость.**

### 2:40–3:20 — Telegram-бот (тот же движок)
- Переключиться на **`@Aqiqat_check_bot`**, **переслать** тот же (или заготовленный
  казахский) пример. Показать, что бот отдаёт **идентичную карточку** + ссылку на `/r/{id}`.
- Тезис: **один backend — три поверхности** (бот, веб-демо, шаринг-страница).

### 3:20–4:00 — Доказательство «живости»: /health и /metrics
- Вкладка **`/health`** — показать JSON: `status: ok`, `llm_provider`, `search_backend`
  (`pgvector`/`e5-inmemory`/`lexical`), `kazllm`, `image_signal`, `cards_stored`.
  Это доказывает, что **система реально запущена и знает, какие бэкенды активны прямо сейчас.**
- Вкладка **`/metrics`** — `checks_total` (счётчик разборов, ненулевой — мы «прогрели»),
  `manipulation_rate` (доля сообщений с манипуляциями). Проговорить: это **измеримый эффект** —
  база для метрики «% сообщений, где пользователь передумал делиться».
- Финальная фраза: *«Объяснимость + казахский контекст + всё работает вживую прямо сейчас.»*

## 2. Уникальная технологическая фича (тезисы, вставлять в питч/Q&A)

1. **Кастомный агентный tool-use оркестратор — не «обёртка над API».**
   `app/orchestrator/` — это агентный цикл из 5 шагов, а не один вызов модели:
   классификация → декомпозиция на атомарные утверждения → **маршрутизация каждого
   утверждения через tool-use** (модель сама решает, звать ли `search_local_corpus`,
   `google_factcheck`, `kazllm_specialist`) → детектор манипуляций → синтез карточки.
   Ручной цикл — `app/services/llm.py::run_tool_loop`.
2. **Локальный специалист по казахскому контексту — KazLLM-8B** (llama.cpp, self-hosted,
   без API-платы). Отдельный инструмент под **kk-контекст**, а не англоцентричная модель
   с переводом. Поиск — multilingual-e5 + pgvector по базе **Factcheck.kz**.
3. **Объяснимая карточка вместо вердикта «97% фейк».** Открытые детекторы дают лишь
   ~78% AUC — врать точностью мы не будем. Показываем **что проверяемо, что нашлось
   в источниках, какие приёмы использованы** — итоговое решение за пользователем.
4. **Честный второстепенный дипфейк-сигнал (ELA + EXIF)** — `services/image_forensics.py`.
   Это **сигнал подозрительности, а не вердикт**: ELA (уровни ошибки JPEG) + теги
   редакторов/AI в EXIF, всегда с дисклеймером, только на собственном демо-материале.
   **Проговорить как границу MVP, а не прятать** — это в плюс по критерию честности.

Доказательная база (для Q&A): манипуляции F1 = 0.97 (precision 0.941 / recall 1.0),
язык kk/ru = 1.0, отделение мнений = 1.0 (см. `MODELING.md` §7, `EVAL.md`).
Стоимость ≈ $0.10 / сообщение при митигациях (см. `COSTS.md`).

## 3. План на случай сбоя на сцене

**Принцип: система НЕ падает — она деградирует управляемо.** Это преимущество, проговорить вслух.

- **Groq упёрся в лимит / недоступен LLM.** Оркестратор автоматически переходит на
  **детерминированный разбор по тем же реальным инструментам** (Factcheck.kz, Google
  Fact Check, rule-based детектор манипуляций). Пользователь всё равно получает карточку.
  Фраза на сцене:
  > «Сейчас LLM-путь недоступен — и это как раз демонстрация нашей устойчивости:
  > система не падает, а переходит на детерминированный разбор по тем же реальным
  > инструментам. Пользователь всё равно получает объяснимую карточку.»
  Это превращает сбой в аргумент по критерию **стабильности**.
- **Не открывается боевой домен / нет сети.** Запустить **резервный скринкаст**
  (локальный видеофайл, заранее скачан на ноутбук) — полный проход демо в записи.
- **Бот не отвечает.** Не тратить время в эфире — показать разбор **на веб-демо** `/`
  (тот же движок) и упомянуть, что бот идентичен.
- **Медленный ответ.** Не молчать: в это время проговаривать тезисы из раздела 2.
- **Резервный источник интернета** — раздать точку доступа с телефона (проверить заранее).

## 4. Пре-демо чек-лист стабильности (за 15–20 мин до выхода)

- [ ] Открыть **`/health`** на боевом домене → `status: ok`. Свериться: `llm_provider`,
      `search_backend`, `kazllm`, `image_signal` — знать текущие значения, чтобы не
      удивляться на сцене.
- [ ] **«Прогреть» демо:** сделать заранее **1–2 разбора** (через `/` или бота), чтобы
      **`/metrics` → `checks_total` был ненулевым** и не позорил на сцене. Обновить вкладку `/metrics`.
- [ ] Проверить, что **бот `@Aqiqat_check_bot` отвечает** — переслать тестовое сообщение.
- [ ] **НЕ запускать локальный поллер параллельно с Railway** — два long-polling
      на один токен дадут Telegram **409 Conflict** и бот замолчит. На демо-ноутбуке
      локальный `python run.py` с тем же токеном должен быть **выключен**.
- [ ] Заготовленные примеры под рукой (см. ниже) — в буфере обмена / заметке, чтобы
      не печатать руками.
- [ ] Проверить **переключатель RU/KK** на лендинге (клик KK → интерфейс на казахском).
- [ ] Проверить, что кнопка **«Поделиться»** и ссылка **«Открыть полный разбор →»**
      действительно открывают `/r/{id}`.
- [ ] **Резервный скринкаст** скачан локально и открывается офлайн.
- [ ] Браузер: вкладки открыты в нужном порядке, зум увеличен для читаемости с проектора,
      тёмная/светлая тема выбрана под экран зала.
- [ ] Телефон-точка доступа заряжена и проверена как резервный интернет.
- [ ] Уведомления/мессенджеры на демо-ноутбуке выключены (режим презентации).
